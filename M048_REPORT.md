# Mission 048 — The Out-of-Box Repair

**Commission:** an independent AI pulled the published v1.27 repo,
installed its one dependency, generated Fern & Co end to end (13/13) —
and reported that the tree does not work out of the box:
`verify:env` fails with "axe-core vendored: missing", the
accessibility/inspection stages will not run until axe-core is
installed and placed in `vendor/axe-core/` by hand, and the layout
suite still reports 40/41. Mohnish: "FIX THE ENGINE MAN."

**Verdict:** fixed, in engine v1.28.0-mission048. The failure was
ours, and it was four missions old.

## 1. Root cause — traced, not guessed

`vendor/axe-core/` (axe.min.js 652,140 B + LICENSE + VERSION.txt,
axe-core 4.14.0, MPL-2.0) shipped in every tree up to M043. The
**Mission 044 slimming dropped it** when the portable candidate was
assembled from selected tiers — along with two smaller files:

| Dropped in M044 | Consequence in v1.24–v1.27 |
|---|---|
| `vendor/axe-core/` | `verify:env` hard-fails out of the box; `engine/inspect.mjs` exits 1 before running; the capability verifier's axe injection fails silently and its accessibility checks go *unmeasured* |
| `package-lock.json` | `npm install` floats transitive dependencies; `npm ci` impossible |
| `requirements.txt` | `verify:env` and `reference_profile.mjs` tell the user to `pip install -r requirements.txt` — a file that does not exist in the tree |

M045–M047 each copied the previous tree, so the hole was inherited
four times and no mission's clean-room caught it, because every
clean-room run followed the generation path — which never touches
axe — and never ran `verify:env` on the extracted tree. That is the
process failure behind the code failure, and §4 closes it with a
suite that runs `verify:env` and `inspect.mjs` as checks.

One part of the external report is **not** a defect: test suites
needing `npm install` first is standard Node practice and is the
README's documented first step; generation itself needs no install
at all. Committing `node_modules` (~27 MB) is not the fix. The real
fix for that half is reproducibility: the lockfile is back, so the
install is pinned and `npm ci` works.

## 2. What v1.28 changes (diff vs v1.27: 13 files — 5 edited, 8 restored/added)

1. **`vendor/axe-core/` restored byte-identical** from the M043 tree
   (md5 `31f2d5f4…` for axe.min.js — the same file that shipped
   before the slimming, not a re-download).
2. **`package-lock.json` restored** (regenerated by a real
   `npm install` on the v1.28 tree; lockfile v3, puppeteer-core
   pinned at 25.16.0).
3. **`requirements.txt` restored** (`Pillow==10.2.0`).
4. **The layout suite's stale check is fixed at the corpus, not
   excused.** Its vocabulary check asserted "the runtime implements
   no component the planner never uses" against a fixed corpus —
   StayNest, CarePoint and three v3 bench layouts — that predates
   the bag (M039), the promo banner (M040) and every declared family
   (M046). By v1.27, 13 real components read as dead code.
   `layout.test.mjs` now also derives and plans a real declared-
   families product brief (the M046 Evira showcase brief, shipped as
   `engine/tests/fixtures/declared-families.product-brief.json`)
   with the engine's own derive + plan, and the corpus covers all
   33 components both ways. **Layout: 41/41** — the standing
   exception carried since Mission 039 is closed.
5. **`run-suites.mjs` exemption removed.** The runner no longer
   treats layout 40/41 as a "known failure" and prints "all suites
   passed" over it. A failure is a failure again.
6. **New suite `design048` (10/10)**, registered in the design
   group: vendored axe present/full/licensed and version-consistent
   with VERSION.txt; requirements.txt and the lockfile pin present;
   `verify:env` exits "ready" on the untouched tree; `inspect.mjs`
   runs end to end on a fixture app; layout passes in full.
7. **Docs made true:** root README version line (it still said
   1.24.0-mission043), its "Verify your install" section now starts
   with `npm run verify:env` and no longer documents the 40/41
   failure as expected; INTEGRATION.md retitled 1.28.0 and its
   environment table now lists the vendored axe-core.

- **Clean room** (the delivered zip, extracted fresh, the external

  design048 10/10 from the extracted tree.

## 4. Limits, stated plainly

- `npm install`/`npm ci` is still required before the browser-driven
  suites — that is the documented, standard step, now pinned. The
  generated app and the generation pipeline need no install, no
  browser and no network.
- The vendored axe-core is 4.14.0, the version the engine's checks
  were built against; upgrading it is a deliberate future change,
  not a drive-by.
- This mission fixed the distribution's out-of-box behaviour. It
  does not change any generated app's design or behaviour: a brief
  generated on v1.27 generates identically on v1.28 (the only engine
  code touched is one test, the runner, and docs).
